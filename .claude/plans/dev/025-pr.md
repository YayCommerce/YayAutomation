**Title:** feat: plan 025 — F2 Workflows table

## Summary

Workflows move from the `yaymatik_wf` post type and its meta to the `workflows` and `workflow_versions` tables (ROADMAP-dev F2.1–F2.4), behind `WorkflowStore`. Every multi-row write runs in one transaction. REST edits and the rate-limit pause share one workflow lock. A version stores its logic and its step positions (layout) apart, so moving a card is not an edit. REST and TS shapes are unchanged.

31 files, about +1080 −640, one commit per checkpoint.

## After pulling: reset your dev data

Nothing is migrated. Workflows saved by earlier dev builds are removed.

1. `./run.sh reset-data` (type `yes`). It deletes the old workflow posts and their meta, drops the workflow, version and run tables, and unschedules YayMatik's jobs. Unsubscribes stay. Running it twice is safe.
2. Load any admin page: the tables are created again (DB version 4).
3. Recreate your workflows from templates.

## Checkpoints
- **CP0 Docs catch-up** (131ab61) — ROADMAP-dev marks M2 done. Design §8 lists the extension filters from PR #28 (`yaymatik_data_item_{id}_fields`, `yaymatik_trigger_provides`, `yaymatik_trigger_refs`). `registerStepPanel` is gone from the docs: plugin steps register through their module, and custom forms wait for the public API (P4).
- **CP1 Tables, WorkflowStore, transactions, reset** (b2b00d8):
  - Schema v4: `workflows` (id, name, status, trigger_id, live / draft version ids, activated_at, created_at, updated_at; one index on status + trigger_id) and `workflow_versions` (replaces `versions`).
  - `WorkflowRepository` → `WorkflowStore`. `active_for_trigger()` is one indexed query on the live rows, no draft read.
  - `create`, `update_live`, `save_draft`, `activate`, `deactivate`, `apply_draft` and `delete` each run in one transaction. A failed write rolls back and returns `yaymatik_save_failed` (500). A version id of 0 can't be stored as live any more.
  - The post type is removed. `./run.sh reset-data` is new.
- **CP2 Shared lock** (c9de049) — `WorkflowStore::locked()` holds the per-workflow `GET_LOCK` (10 s wait, 409 `yaymatik_busy` when not taken). REST uses it, and so does the rate-limit pause in `RepositoryWorkflows::deactivate()`. The pause checks again that the workflow is still active, so a REST Deactivate that got there first doesn't record a second version. If the pause can't take the lock, it logs an error and the Dispatcher still blocks runs in that request.
- **CP3 Layout split + graph helpers** (c2b0b39):
  - `graph` = logic (no positions), `layout` = `{ nodeId: { x, y } }`. Reads merge positions back, so `node.position` is unchanged in REST and TS.
  - Moving a card writes only the layout of the row being edited (draft, else live): no draft, no version, no `updated_at` change. A draft edited back to the live logic is cleared and its positions go to the live row. Activate and deactivate copy the layout to the new version.
  - Editor: "Draft changes" shows only when the logic differs (`sameLogic()` in `model/graph.ts`), so dragging a card on an active workflow no longer flashes it.
  - `GraphSchema::trigger()`, `parents()` and `by_id()` replace duplicated code in the Validator, Executor, Dispatcher and EmailPreview.
- **CP4 Storage check + wrap-up** (b18cc88) — `./run.sh check-storage` covers the whole lifecycle through REST (see How to test). Docs: ROADMAP-dev F2 ⏳, M7.4, V12.2 and M8 follow-ups; design §2 says what deleting a workflow leaves behind.

## Behavior changes
- Moving a card on an active workflow makes no draft and no version, and doesn't change "Last updated".
- A database error while saving returns 500 "Couldn’t save the workflow. Try again." and nothing is written.
- A failed lock query returns 500 at once, without the 10 s wait.
- Deleting a workflow deletes its versions. Its runs stay until retention cleanup (M7.4).

- **Scripted (wp-cli), on a site just reset:**
  - `./run.sh check-storage`: create → edit before activation (live row updated in place) → activate → move a card (no draft, no version, times kept) → draft → move a card in the draft (draft row only) → apply (the draft row becomes live) → deactivate (layout copied) → delete (versions gone). Version ids are never 0.
  - Rollback: a `query` filter breaks the `workflow_versions` INSERT. Activate returns 500 and nothing changes. Create returns 500 and leaves no workflow row.
  - Lock: a `query` filter breaks the `GET_LOCK` query. REST Deactivate returns 500 `yaymatik_save_failed` at once, and the workflow stays active on the same version.
  - `./run.sh check-runs`: the rate-limit pause deactivates under the lock and cancels waiting runs. With the lock held by another connection, REST returns 409 and the pause logs and leaves the workflow on.
  - `check-orders`, `check-status-flow`, `check-late-module` pass.
