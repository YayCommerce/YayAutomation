**Title:** feat: M1 PR B — customer email UI, coupon form, first-order thank-you templates

## Summary

The UI half of M1 (plan 018), on top of the backend from #19. Merchants can now write customer emails in a rich editor, preview them or send a test, set up a single-use coupon and start from the two First-order thank-you templates.

### B1 — Rich editor for `html` fields (`0050eaa`)
- `RichTextEditor`: WordPress's classic editor (TinyMCE + Quicktags) with Visual / Code tabs, mounted outside React through `classicEditor.ts`. Mount and unmount are clean, StrictMode's double mount included.
- "Insert variable" puts the tag at the cursor in either tab. A block (e.g. the coupon box) goes in its own paragraph.
- `onChange` only fires on a real edit, so opening a step never rewrites its stored HTML.
- `StepForm` draws every `html` field with it, so Send internal email gets it too. The TS defaults for that step are gone (PHP owns them).
- PHP `AdminPage` calls `wp_enqueue_editor()`.
- Known: the content inside the editor stays light in dark mode, because it's an iframe with WordPress's own styles.

### B2 — Send email panel (`a051e06`)
- Send email uses the generic form, plus two new `defineStep` slots: `Footer` (the unsubscribe note) and `Actions` (Preview / Send test in the panel header).
- Preview dialog: a mail-client header (sender, subject, To), then the server's HTML in a sandboxed iframe sized to its content, with Desktop / Mobile widths. It shows a "Sample data" badge, or the order number whose data it uses.
- Send test goes to the logged-in user with a `[Test]` subject. A step the server refuses lists its issues in the panel.
- "Blocks" group in Insert variable (rich text only), one section per Generate coupon step.
- Stub entries removed from `pending.ts`. `customer.unsubscribed` and the boolean operators now come from PHP.

### B3 — Generate coupon from PHP fields, step issues in panels (`275e6c6`)
- Generate coupon's custom `Form.tsx` / `schema.ts` are deleted. The form is drawn from PHP `fields()`, and `normalize()` reads older configs that stored numbers as text.
- The card reads e.g. "10% off, expires in 30 days" (or "never expires").
- Free shipping warning in the panel when no shipping method takes a free shipping coupon, linking to WooCommerce → Shipping. When the only methods also need a minimum order amount, the warning says that instead. It's a notice only and never blocks Activate.
- Rules only PHP checks (e.g. a percentage over 100) come back from autosave. They show under their field, or at the top of the panel, and give "Needs setup" on the card if the panel is closed. They clear once the step changes.
- Validator (PHP + TS) has clearer messages for step outputs: "comes from a step that isn't in this workflow anymore" and "needs the Generate coupon step above this one". They block Activate.
- Condition: Is true / Is false checked for yes/no fields.

### B4 — Templates and library (`3a81ab3`)
- First-order thank-you ×2 (10% off / free shipping, 30 days) run on `customer.is_first_order`. Their HTML messages are built with `emailMessage()` and include the coupon box.
- Subject "Thanks for your first order — a gift for your next one"; the greeting falls back to "there" when there's no first name (`527b0dc`).
- Cross-sell / upsell templates use the coupon box too. They stay locked until Wait (M2).
- The template `workflow` key replaces `popularity`. It drives "Other versions" in the template preview and a fixed "Most popular" order.
- "Before you start" in the preview when a free shipping coupon needs a shipping method set up.
- Templates that email customers say "Review the emails, then activate it" (preview note and toast).

### B5 — Verify and docs (`07ac922`)
- `docs/ROADMAP-dev.md`: M1 marked (backend ✅, UI and templates ⏳), with what moved and the follow-ups.
- `docs/workflow-core-design.md` §5 / §6 updated to match what PR B built.

## How to test

Setup: `define( 'YAYMATIK_IS_DEVELOPMENT', true );` and `pnpm dev`, or `pnpm build`. Mailpit (or any local mail catcher) helps for Send test.

1. **Rich editor**: open a Send email or Send internal email step.
   - Type in Visual and in Code, switch tabs, and use Insert variable in each tab: the tag lands at the cursor.
   - Close and reopen the panel: no autosave fires if nothing was edited.
2. **Preview / Send test**:
   - In a Send email step, click Preview. It should show the latest paid order's data ("Order #N data"). With no paid orders, or a trigger without orders, it shows "Sample data".
   - Switch between Desktop and Mobile.
   - Send test from the dialog and from the menu: the mail arrives at your address with a `[Test]` subject.
   - Clear the To field and click Preview: "Fix this step first" lists the issue.
3. **Coupon box**: add a Generate coupon above a Send email step. In the message, Insert variable → Blocks → coupon box. Preview shows the box with `YMSAMPLE`.
4. **Generate coupon**:
   - Check that the card text follows the settings.
   - Enter amount 150 with Percentage: the error shows under Amount after the save.
   - Choose Free shipping with no shipping method set to take a coupon: the warning and its link appear, and Activate still works.
5. **Step issues**:
   - Move the Generate coupon step below the email, or delete it: the email step gets the "needs the … step above" or "isn't in this workflow anymore" issue.
   - Activate is blocked.
6. **Templates**:
   - Library: "Most popular" order is fixed; filter by category.
   - Open First-order thank-you (discount): "Other versions" links to the free shipping one.
   - On the free shipping version, "Before you start" shows when shipping isn't set up.
   - Use template: the toast says "Review the emails".
   - Activate it, complete a first order: the customer gets the email with a coupon. A second order sends nothing.
7. **Dark mode**: the panel, tabs, dialog and warnings follow the theme. The editor's content area stays light.

Checks: `pnpm lint`, `pnpm test` (206), `pnpm test:php` (452), `pnpm lint:php` and `pnpm build` all pass.
