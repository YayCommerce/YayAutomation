**Title:** feat: plan 030 — custom workflow catalog: 6 triggers, new condition fields and groups, 4 actions

## Summary

Shop owners can now build their own workflows from New Workflow, not only start from a template. This PR adds:
- **6 triggers:** Order paid, Order refunded, Order note added, Customer order count reaches, Customer total spend reaches, Review posted.
- **About 25 condition fields**, with list, relative-date ("in the last N days"), "is set" and custom-field comparisons, plus one level of condition groups.
- **4 actions:** Update customer custom field, Change customer role, Resend WooCommerce email, Wait until.
- **A fix** to Update order custom field.

Every write action is guarded at run time, because runs execute as user 0.

Base: `develop` f747ff8. **No schema change:** the claims table keeps its column, and guest claim keys are hashed to fit it. One commit per checkpoint, plus `fix:` commits from review. Built in three runs: CP0–CP6, CP7–CP10, CP11–CP16.

No migration: a stored `hour` config reads as a setup issue in PHP and on the card (checked in `check-catalog`).

## Worth a closer look
- **Run-time guards for user-0 writes:** `MetaKeys::user_collides()` (per user, no DISTINCT, a failed read refuses), `ChangeCustomerRole::user_protected()` / `role_protected()`, and `UpdateCustomerMeta`, which slashes its key and value so the stored key is the one checked.
- **The active-trigger cache race** (`WorkflowStore::refresh_active_triggers()`): readers store with `INSERT IGNORE`, and writers rewrite under one lock. `check-catalog` simulates two interleaved writers from a second process.
- **Order paid on an order saved already paid** (`OrderPaidTrigger`). WooCommerce fires `woocommerce_new_order` for drafts too, so the order is caught around its first save, not at that hook.
- **Milestone claims** hash a guest's email. The Worker releases the claim through `scope.trigger.claim_key`.
- **Runs keep refs only.** Step results are ids, keys, fixed labels or booleans: role names, an email's id, a count, a store-time date. "Sent Completed order" never names the address.
- **`PROTECTED_CAPS` allows customer rights only.** On top of D8's staff and site capabilities: `edit_posts`, `publish_posts`, `edit_others_posts`, `edit_pages`, `upload_files`, `moderate_comments`, `edit_products`, `edit_shop_coupons`, `manage_product_terms`, `view_woocommerce_reports`, `import`, `export`. Triggers fire on public events, so any buyer would get the role, and customer roles only need `read`. Author, Editor and Contributor aren't assignable.
- **Known limits** are under Cost in `docs/workflow-core-decisions.md`, section CT.

## How to test
- `./run.sh check-catalog` checks HPOS and the posts store, the second through its own process. It stops if the site has an active workflow on these triggers, so deactivate those first.
- Also `check-winback`, `check-lifecycle`, `check-carts`, `check-runs`, `check-orders`, `check-storage`, `check-late-module`, and `check-status-flow <two order ids>`.
- Editor:
  - Build a condition with each rule kind and a group. Search, reload: the labels stay.
  - Order status changed + Change order status shows the amber may-refire line.
- Triggers:
  - Order paid: a pending checkout marked processing gives one run; completed after that gives none.
  - Refunds: a partial refund, then the rest, give two runs, Full refund No then Yes.
  - Review posted: a review held for moderation gives no run until it is approved.
- Actions:
  - Update customer custom field: `wp_capabilities` shows an issue.
  - Change customer role: the list has customer roles only (no Administrator, Shop manager, Editor, Author or Contributor); on a shop manager the step is skipped.
  - Resend Completed order: the email arrives.
  - Wait until: Time is a 160px time input (any minute) with a Clock button that opens the picker and the help line about scheduled tasks under it; typing still works; a new step starts at 9:00 am; type 11:10 and the card reads "Until 11:10 am · Mon–Fri" (with 24-hour site time, "Until 11:10"); the hint under the form has a clock icon and shows the store time zone; cleared, it reads only "Store time (…)." The clock button shows in dark mode.
