**Title:** feat: plan 033 — privacy lookup index, cart lock on series start, Skipped runs for refused cart claims

## Summary

This PR must ship before the WordPress.org submission.
- **Privacy lookups use an index.** Export and erase used to scan every run and every step's JSON on each page. Now they read a new `run_emails` table plus `runs.subject`. At 200k runs a page takes about 4 ms instead of 5.5 s.
- **A cart is locked only when a series starts.** An abandon that no active workflow takes leaves the cart free. The same cart can then start the Checkout reminder when the shopper leaves at checkout later.
- **Refused cart claims show up.** A cart claim refused because the cart already has a series, the cart was ordered, the shopper unsubscribed, or the email had a series in the last 7 days now records a Skipped run with that reason. It shows under the existing Skipped tab.

Base: `develop` 9b31ca7. **Schema change: DB 7 → 8** (new `run_emails` table, `KEY subject (subject, status)` on `runs`). **No backfill:** after deploy, run `./run.sh reset-data --staging` (then `seed`) on staging and on each tester site, or runs written before 033 can't be found by export and erase. Then `./run.sh probe-mysql --staging`.

One commit per checkpoint; CP3 and CP4 share one.

## Side effects
- `yaymatik_cart_abandoned` fires on every abandon, a cart already in a series included, not once per cycle, and gains `$kind`. It is experimental, like the other hooks.
- A cart in a series that is abandoned again records a Skipped run "This cart already got a reminder series." each time, in the workflows of that abandon's kind.
- Skipped runs count in the overview's Runs (30 days) and Last run, and toward the 1000-runs-per-minute ceiling. A sweep is at most 200 carts, so skips alone can't pause a workflow.

## WordPress.org review notes
- `RunStore::index_emails()` takes `$runs`, a fixed `SELECT … FROM %i WHERE id = %d`-style fragment written in `RunStore` / `RunStepStore`, with its values passed separately. `about()` returns a fixed derived-table fragment the same way. As with `$filter` and `Schema::in()`, no value from a request or the database is written into the SQL text.

## Browser check for Jack (UI only)

### 0 Before you start
- A cart gets at most one reminder series until it is ordered. An email gets at most one series in 7 days.
- The abandon that starts the series decides its kind (Cart or Checkout). An abandon that no workflow picks up does not lock the cart.
- A refused abandon (ordered, unsubscribed, or a series already in 7 days) shows a Skipped row with its reason in Workflow runs.

### 1 Setup
- The test site has 033 deployed and has run `./run.sh reset-data`, then `seed`.
- Settings › Cart tracking: turn it on; set "Count a cart as abandoned after" to 15 minutes; Save changes.
- Create 2 workflows from templates: Abandoned cart reminder (Cart abandoned) and Abandoned checkout reminder (Checkout abandoned). Leave both off for now.
- A customer account with an email, logged in in another browser (or a private window).
- To skip the wait: WooCommerce › Status › Scheduled Actions, find `yaymatik_cart_sweep`, and click Run once the cart has been idle 15 minutes.

### 2 Steps

**B1. Cart only**
- Goal: a cart left on the cart page starts Cart reminder.
- Do: turn on Abandoned cart reminder. The customer adds 1 product to the cart, does not go to checkout, and leaves for 15 minutes. Run the sweep.
- Pass when: the Cart workflow has 1 run (Running/Waiting/Completed), and the reminder email reaches the customer's inbox.
- Why: an active workflow picks up this abandon and starts the series.

**B2. Checkout only**
- Goal: an abandon before checkout does not use up the later Checkout reminder.
- Do: turn off Cart, turn on Checkout. A new customer (another email) adds a product, leaves for 15 minutes, run the sweep. Then the customer comes back, goes to the Checkout page, leaves for 15 minutes, run the sweep.
- Pass when: after the first leave, Checkout has no runs; after the second, it has exactly 1 Checkout run, and the checkout reminder email arrives.
- Why: no workflow picked up the first abandon, so the cart was not locked.

**B3. Both on**
- Goal: a cart never gets two reminder series.
- Do: turn both on. A new customer adds a product, leaves for 15 minutes, run the sweep (Cart starts). The customer comes back, goes to Checkout, leaves for 15 minutes, run the sweep.
- Pass when: only the Cart workflow has 1 run for this cart; Checkout has no runs; the inbox has only the Cart email.
- Why: the cart already has a series, so the later abandon does not start a new one.

**B4. Admin retries with the same cart**
- Goal: a repeat attempt shows up instead of passing silently.
- Do: reuse B1's account and cart (not ordered). The customer comes back to the cart page and leaves for 15 minutes. Run the sweep.
- Pass when: Abandoned cart reminder's Workflow runs › Skipped tab has 1 new row; opening it shows "This cart already got a reminder series."; no new email; the workflow still has only 1 real run for this cart.
- Why: a cart gets one reminder series. Before 033 this attempt left no trace, so testers thought the workflow was broken.

**B5. Privacy: export and erase**
- Goal: export finds the customer's runs, Skipped ones included; after erase, export no longer finds them.
- Do: Tools › Export Personal Data, enter B1's email (it has the Cart run from B1 and the Skipped run from B4), Send Request, then click "Download personal data" on the request row. Then Tools › Erase Personal Data, enter the same email, click "Erase personal data". Finally, export again.
- Pass when: the first export file has a YayMatik runs section with the Cart run (B1) and the Skipped run (B4). Erase reports done. The second export has no YayMatik runs (only the unsubscribe record, if any).
- Why: export and erase now find runs through the index table instead of scanning everything.
