**Title:** feat: plan 033 — privacy lookup index, cart lock on series start, Skipped runs for refused cart claims

## Summary

This PR must ship before the WordPress.org submission.
- **Privacy lookups use an index.** Export and erase used to scan every run and every step's JSON on each page. Now they read a new `run_emails` table plus `runs.subject`. At 200k runs a page takes about 4 ms instead of 5.5 s.
- **A cart is locked only when a series starts.** An abandon that no active workflow takes leaves the cart free. The same cart can then start the Checkout reminder when the shopper leaves at checkout later.
- **Refused cart claims show up.** A cart claim refused because the cart already has a series, the cart was ordered, the shopper unsubscribed, or the email had a series in the last 7 days now records a Skipped run with that reason. It shows under the existing Skipped tab.

Base: `develop` 9b31ca7. **Schema change: DB 7 → 8** (new `run_emails` table, `KEY subject (subject, status)` on `runs`). **No backfill:** runs written before 033 aren't indexed, so export and erase can't find them. Staging: after deploy, run `./run.sh reset-data --staging`, then `seed`, then `./run.sh probe-mysql --staging`. Tester sites: no reset; test only with emails never used on that site.

One commit per checkpoint; CP3 and CP4 share one.

## Side effects
- `yaymatik_cart_abandoned` fires on every abandon, a cart already in a series included, not once per cycle, and gains `$kind`. It is experimental, like the other hooks.
- A cart in a series that is abandoned again records a Skipped run "This cart already got a reminder series." each time, in the workflows of that abandon's kind.
- Skipped runs count in the overview's Runs (30 days) and Last run, and toward the 1000-runs-per-minute ceiling. A sweep is at most 200 carts, so skips alone can't pause a workflow.

## WordPress.org review notes
- `RunStore::index_emails()` takes `$runs`, a fixed `SELECT … FROM %i WHERE id = %d`-style fragment written in `RunStore` / `RunStepStore`, with its values passed separately. `about()` returns a fixed derived-table fragment the same way. As with `$filter` and `Schema::in()`, no value from a request or the database is written into the SQL text.

## Browser check for Jack (UI only)

### 0 Before you start
- A cart gets at most one reminder series until it is ordered. An email gets at most one series in 7 days.
- The abandon that starts the series decides its kind (Cart or Checkout). An abandon that no workflow picks up does not lock the cart.
- A refused abandon (the cart already has a series, it was ordered, the email unsubscribed, or the email already had a series in 7 days) shows a Skipped row with its reason in Workflow runs.
- Timing: a cart counts as abandoned after 15 minutes idle, and the site checks carts every 5 minutes. So after leaving, **wait about 20–25 minutes and reload the Workflows page now and then**. Both templates then wait 1 hour before emailing: the run shows "Waiting" first, and the email arrives about 1 hour later.

### 1 Setup
- Plugins › Add New Plugin › Upload Plugin: upload the 033 zip and choose "Replace current with uploaded". Then YayCommerce › YayMatik › Settings › Health check › Check again.
- Use only customer emails never used on this site. Runs written before 033 aren't indexed, so export and erase won't find them.
- Settings › Cart tracking: turn on "Track carts"; set "Count a cart as abandoned after" to 15 minutes; Save changes.
- Workflows › Browse templates: create "Cart reminder" and "Checkout reminder". Leave both off for now.
- Three customer accounts with different emails (A, B, C). Each customer uses a separate browser or private window, logged in there.
- An inbox to read the emails (or the site's mail log, if there is one).

### 2 Steps

**B1. Cart only**
- Goal: a cart left on the cart page starts Cart reminder.
- Do: turn on "Cart reminder". Customer A adds 1 product to the cart, does not go to Checkout, and closes the tab. Wait about 20–25 minutes and reload Workflows › Cart reminder a few times.
- Pass when: Cart reminder's Workflow runs has 1 "Waiting" run for A's cart. About 1 hour later, A gets the email "You left something in your cart".
- Why: an active workflow picks up this abandon and starts the series.

**B2. Checkout only**
- Goal: an abandon before Checkout does not use up the later Checkout reminder.
- Do: turn off "Cart reminder", turn on "Checkout reminder". Customer B adds a product, does not go to Checkout, and closes the tab. Wait about 20–25 minutes and reload Checkout reminder. Then B opens the site again, goes to the Checkout page, and closes the tab. Wait about 20–25 minutes and reload a few times.
- Pass when: after the first leave, Checkout reminder has no runs. After the second, it has exactly 1 "Waiting" run for B's cart. About 1 hour later, B gets the checkout reminder email.
- Why: no workflow picked up the first abandon, so the cart was not locked.

**B3. Both on**
- Goal: a cart never gets two reminder series.
- Do: turn both on. Customer C adds a product, does not go to Checkout, and closes the tab. Wait about 20–25 minutes and reload: Cart reminder has 1 run for C's cart. Then C opens the site again, goes to the Checkout page, and closes the tab. Wait about 20–25 minutes and reload a few times.
- Pass when: Cart reminder still has only 1 real run for C's cart. Checkout reminder has no real runs, only 1 row in the Skipped tab: "This cart already got a reminder series.". C gets only the Cart email.
- Why: the cart already has a series, so the later abandon does not start a new one; it only records the reason.

**B4. Same cart again**
- Goal: a repeat attempt shows up instead of passing silently.
- Do: keep "Cart reminder" on. Customer A (the cart from B1, not ordered) opens the site again, goes to the cart page, does not go to Checkout, and closes the tab. Wait about 20–25 minutes and reload Cart reminder a few times.
- Pass when: Cart reminder's Workflow runs › Skipped tab has 1 new row; opening it shows "This cart already got a reminder series.". A gets no email beyond the one from B1, and Cart reminder still has only 1 real run for this cart.
- Why: a cart gets one reminder series. Before 033 this attempt left no trace, so testers thought the workflow was broken.

**B5. Privacy: export and erase**
- Goal: export finds the customer's runs, Skipped ones included; erase removes the email from those runs and keeps the runs.
- Do: Tools › Export Personal Data, enter A's email (it has the Cart run from B1 and the Skipped row from B4), click Send Request, then click "Download personal data" on the request row. Then Tools › Erase Personal Data, enter the same email, click "Erase personal data". Finally, export again.
- Pass when: the first export file has a YayMatik runs section with the B1 run and the B4 Skipped row. Erase reports done. The runs are still in Cart reminder's Workflow runs: the Subject column shows "Cart #N" (no email), and opening the run shows "Sent to [deleted]" on the Send email step. The second export has no YayMatik runs (only the unsubscribe record, if any).
- Not a bug: after erase, WooCommerce may report that some data was not erased (download permissions). That is WooCommerce's data, not YayMatik's.
- Why: export and erase now find runs through the index table instead of scanning everything.
