**Title:** feat: plan 024 — M2 PR B: Runs UI

## Summary

The M2 UI (ROADMAP-dev M2.6–M2.10) on top of PR A's backend. The overview gets a runs table and a run detail sheet. The list and the overview summary fill Runs (30 days) and Last run. Deactivate and Update say how many waiting runs they cancel. The product grids become blocks in "Insert variable", and the grid now looks right in email clients. The 4 cross-sell / upsell templates were checked end to end.

44 files, about +1420 −210, one commit per checkpoint plus 2 small fixes.

## What changes
- **List and summary row:** Runs (30 days), and Last run as "2 hours ago" (full date and time on hover). Under it is how that run ended (Failed in red), linked to `/workflows/<id>?run=<id>`. A workflow that never ran shows "—" in both.
- **Runs table** (overview), newest first:
  - Columns: Started, Subject (link to the order), Status, Steps run.
  - Statuses: Running (queued shows as Running), "Waiting until Oct 9 at 3:00 PM", Completed, Failed, Cancelled, Skipped. A run's reason shows under its badge.
  - Filter: All · Running · Waiting · Completed · Failed · Cancelled · Skipped.
  - Pages come from the server's `perPage`. Skeleton rows while loading. "No runs yet" while it has never run.
- **Run detail:** a sheet from the right, opened from a row or by `?run=<id>`, so reload and shared links work. The header has the subject link, status, and started / finished times. Then the trigger, then each step that ran with its result and time:
  - Yes / No for a condition.
  - "until …" for a waiting Wait, or "Wait 1 day, resumed …" once it resumed.
  - "Sent to …" for an email.
  - The code for a coupon.
  - The card summary for any other step ("Set to Completed").
  - The reason for a step that was skipped, failed or cancelled.
  - A step whose node is gone reads "Removed step".
  - A missing run, or another workflow's run: the toast says "Run not found." and the param is removed.
- **Deactivate / Update dialogs** (editor, overview, row menu, bulk) say "N waiting runs will be cancelled." (left out when 0; for bulk, the sum). The Deactivate text is now "Runs under way stop before their next step". The Update text adds "Runs under way finish on the version they started on." The success toasts give the real `cancelledRuns`. Deactivate and Update refresh that workflow's runs.
- **Insert variable:** the product grids (`order.cross_sell_products` / `upsell_products`) appear under Blocks, in a section named "Order", in rich text fields only. The Blocks row moved out of "From earlier steps" and has a neutral tile.
- **Product grid look** (`Email\ProductGrid`, email-client safe):
  - Each image sits in a grey square of up to 160px, its size scaled from the real thumbnail. The square and the image shrink on narrow phones.
  - Names are cut at 60 characters. The price is grey under the name.
  - An odd last product is centered.
  - The grid has the coupon box's width and spacing.
  - It sets its own padding and margins, so WooCommerce's inlined email CSS can't override them. Text mode is unchanged.
- **PHP:**
  - Workflow stats add `lastRunStatus` and `lastRunId`. All three last-run fields come from the newest run by id, in one query.
  - The runs list adds `perPage`.
  - `GET /runs/{id}` adds `subjectLabel` / `subjectUrl`.
  - The cancel reason is now "The workflow was deactivated.".
  - A skipped email's reason is now "The customer unsubscribed from these emails." (was the code `unsubscribed`).
- **Roadmap:** ROADMAP-dev marks M1 ✅, M2.1–M2.5 ✅ and M2.6–M2.10 ⏳. ROADMAP-v1.0's Workflow list and overview text match what was built.

## Decisions
- **D1:** The first commit only marks M1 and the M2 backend done.
- **D2:** No Wait code change. The card reads "Wait 1 day" with the clock icon, under YayMatik › Flow. Its custom form stays, because the generic form can't draw `number_unit`.
- **D3:** The runs table, its statuses and its filter, with Skipped added (see Changes vs plan).
- **D4:** The page size comes from PHP (`RunStore::PER_PAGE`, 20); TS has no constant.
- **D5:** Run detail is a sheet driven by `?run=`, showing only the steps that ran. There's no canvas path view.
- **D6:** One TS map gives each step type its result text. Skipped / failed / cancelled steps show their reason.
- **D7:** Links go to orders only; customer links come with M4.
- **D8:** Last run shows how the run ended, linked to it, as in identity mock v2.
- **D9:** The dialogs use `waitingRuns`, and the toasts use `cancelledRuns`.
- **D10:** Runs refresh after Deactivate / Update. There's no polling.
- **D11:** The cancel reason reads "The workflow was deactivated.".
- **D12:** Block data fields become block variables, in html fields only.
- **D13:** Manual end-to-end check of the 4 templates.

## Changes vs plan
- **Skipped:** `skipped` is a real run status. `Worker::start()` sets it when the order is gone before the run starts. So Skipped has its own label and filter tab and counts as a last run.
- **Run detail subject:** `GET /runs/{id}` returns `subjectLabel` / `subjectUrl`, because a `?run=` link needs the header without the list.
- **Order status result:** change_order_status has no result text of its own; its card summary already reads "Set to Completed".
- **API hooks:** they landed with their first caller (CP3 / CP4), not in CP1.
- **Dialog text:** Deactivate keeps "You can activate it again at any time." (Jack). Each dialog text is one whole translatable string, not joined sentences.
- **CP6b (added):** the product grid look, including the narrow-phone fix.
- **2 fixes:**
  - Opening a run replaces the URL, as closing does, so Back leaves the overview.
  - The readable unsubscribe reason.
- **Helpers moved:**
  - `shortDay` / `shortDayTime` moved to `lib/helpers/date.helper.ts`.
  - The list's compact tab classes moved to `shared/ui/tabs.ts`.
  - The 404-aware retry is shared by the workflow and run queries.

## Behavior changes
- A run cancelled because its workflow went off reads "The workflow was deactivated." (was "turned off"). This includes the rate-limit pause.
- A skipped email reads "The customer unsubscribed from these emails." in run history.
- The Deactivate text changed. The old "Runs already under way will finish" was wrong since PR A.
- The product grid HTML changed: fixed squares, cut names, a centered odd product.

## Follow-ups (not in this PR)
- A workflow runs again when the same order is completed again (duplicate email / coupon); consider a once-per-order guard.
- A run that ends at a Condition's No path shows Completed like one that sent an email; consider a short outcome in the runs table (e.g. "Stopped at Condition (No)").
- Preview picks a recent order that may have no cross-sells / upsells: the product grid is then empty, with no hint why.
- Product grid: the square's grey and the price color are fixed, not the store's email colors. In Outlook desktop (Windows) the square fills its column (max-width ignored).
- Insert variable (from F1.12): the customer shows twice when the trigger provides both order and customer. Once as the Customer group (`customer.*`), and again as the Customer section inside Order (`order.customer.*`). Option: hide a relation's section when its item is already a top-level group. The Order count (21 = 12 order fields + 9 customer relation fields; the 2 product grids are in Blocks) is correct.
- Kit Pagination (`components/ui/pagination.tsx`) has hard-coded English ("Page X of Y", "Go to") → M9.2.
- Dialog counts come from cached stats, so they can be a little out of date; the toast always has the real number.
