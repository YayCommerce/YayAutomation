## Summary

One repo now builds two plugins. **YayMatik** (free, WordPress.org) has 9 triggers, 6 actions, flat conditions with fixed values, and 8 templates. **YayMatik Pro** (`yaymatik-pro`, installed instead of the free plugin) adds 3 triggers, 5 actions, groups, compare-with-another-field, custom-field rules, 17 data fields, 10 templates and the wider settings ranges. The free zip carries no Pro code, and a store that moves from Pro to the free plugin loses no data and never runs a workflow half-way.

- **Folders (D0, D1):** all Pro code lives in `includes/Pro/` (namespace `YayMatik\Pro\`) and `apps/admin-page/src/pro/`, mirroring the free paths. Free code never imports Pro; the one exception is the `Pro\Boot` call in `YayMatik::initialize()`.
- **Switches (D3, D4):** `Pro\Boot::register()` registers the Pro license and, while it allows features, swaps in the Pro modules on `yaymatik_modules`, widens the settings ranges and adds the customer-meta-keys route. `Pro\Boot::boot()` (init, priority 0) adds the inactive sweep. In JS, the Vite alias `@edition/*` (`steps`, `templates`, `health`, `criteria`, `settings`, `teaser`) points at `src/lite/` or `src/pro/` according to `YAYMATIK_EDITION`.
- **License (D16, YayCurrency's pattern):** `YayMatikProLicenseAdapter` implements admin-shell's `LicenseConfigAdapter`; `is_licensed()` calls `LicenseState::allows_features( 'yaymatik-pro' )`, so an expired key keeps Pro and a `disabled` one doesn't. The item id is temporarily **7761 (YayCurrency)**. Guard 1: `release.sh pro` refuses while it's temporary, except with `--rc`. Guard 2: `UpdateBlock` hides the updater's offer (no Update button, no "View details", no auto-update).
- **Free edition knows Pro by name only (D5):** `ProCatalog` lists the step ids (kind, label, outputs), field keys and condition features; `ProCatalog::missing()` is what this site lacks (empty with Pro and a license).
- **Needs YayMatik Pro (D6):** `ProUsage` names the steps of a workflow that use a missing Pro part. Such a workflow keeps its config on read and save, gets the `needs_pro` issue (no Activate / Update), never starts (Dispatcher), and a waiting run is cancelled before that step ("Needs YayMatik Pro."). The editor draws those steps greyed and read-only; the Health check lists active ones (`needs_pro`).
- **Settings (D7):** reading keeps the full ranges. The free edition saves retention up to 60 / 90 days and doesn't show abandon minutes; values stored by Pro keep working until the owner saves a new one.
- **Teaser (D13):** one "PRO" group, free edition only, last in the trigger and action pickers and under the template library; it opens `https://yaycommerce.com/yaymatik/`. No locked controls.
- **Release (D2, D14):** `./run.sh release` bundles the JS as lite, then `dev/scripts/lib/check-lite-zip.sh` fails the build if the zip holds `includes/Pro`, a Pro step or template id, or `yaymatik-pro`. `./run.sh release pro` builds `yaymatik-pro/yaymatik-pro.php` ("YayMatik Pro", `Update URI`). With both active, `Fallback.php` deactivates the free one (proved in `check-plugin-lifecycle`).
- **Extension API core list (D12):** `docs/extension-api-core.md` and `tests/fixtures/extension-api-core.json` give every step and data key a tier, `lite` or `pro`.

Base: develop `1a58c38`. **No schema change.** New options: none in the plugin (`yaymatik_dev_edition` exists only in the wp-env mu-plugin).

### 1 License (Pro zip)

### 2 Free zip

3. Condition form: no "Add group", no compare-with button, no custom field in the data list.
4. Settings: with cart tracking on, no "Count a cart as abandoned after"; retention fields say 7 to 60 and 7 to 90.

### 3 From Pro to free and back (wp-env)
1. On Pro: use Win-back discount (Pro trigger) and a condition with a group; activate both.
2. `wp option update yaymatik_dev_edition lite`, reload: the workflows show the Pro steps greyed with "Needs YayMatik Pro…"; Activate shows the issue; Settings › Health check lists them under "Active workflows need YayMatik Pro".
3. Change the workflow's name and save: it saves; the condition still shows its group when back on Pro (`wp option delete yaymatik_dev_edition`).
