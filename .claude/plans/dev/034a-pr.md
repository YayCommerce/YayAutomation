**Title:** feat: plan 034 PR A — Extension API v1: registrar, yaymatik_fire, Run, data fields and facts, missing plugin

## Summary

Other plugins can now add triggers, actions, data fields and data items to YayMatik through one hook, with arrays, without extending a YayMatik class (`docs/extension-api.md`, agreed Nov 13; public surface simplified 11:47).
- **Declare:** `add_action( 'yaymatik_register', fn( $r ) => $r->module( [...] )->trigger( … ) )`. Fields and types are arrays and type names; callbacks are any PHP callable.
- **Fire:** `do_action( 'yaymatik_fire', $trigger_id, [ 'user_id' => …, 'points' => … ] )`. Payload ids become the run's data and subject (order → cart → review → user → the module's item), declared facts become `trigger.<key>`. The event takes the core path: Dispatcher, claims, run ceiling, loop guard.
- **Run:** an action's `run( $config, $run )` returns `$run->done()` / `skip()` / `fail()`; `$run` reads `order()`, `user()`, `customer_email()`, `cart()`, `item()`, `get()`, `render()`.
- **Isolation:** every plugin callback runs in a guard: a throw becomes a diagnostic in Settings › Health check › Extensions, never an error in core. A deleted entity still skips the step as in core ("Order no longer exists.").
- **Plugin turned off:** its steps stay in the workflow (greyed, read-only), the workflow saves but can't be activated (`missing_plugin`), an active one keeps running and skips those steps ("Acme Rewards isn't active."), and Health check lists it.

Base: `develop` 6be688a. **No schema change** (two options: `yaymatik_extension_errors`, `yaymatik_extension_steps`, both autoloaded). Core behaviour for 1.0 workflows is unchanged; every core edit is listed under "Core changes".

## Browser steps (Jack)

### 0 Understand
Another plugin (the "Acme Rewards" example) adds a trigger, an action, a customer field and a fact. Its trigger starts when the plugin calls `yaymatik_fire`. When the plugin is turned off, its steps stay but can't run.

### 1 Prepare
- Local site on this branch's zip, or `pnpm dev`.
- Copy `.claude/local/034-example-acme.php` to `wp-content/plugins/acme-rewards/acme-rewards.php`. Delete its section 5 (email action) and section 6 (template): they come in PR B. Add any one-colour 24×24 `logo.svg` beside it. Activate "Acme Rewards for YayMatik (example)".
- Two customer accounts (A, B), each with an order you can set to Completed. Cash on delivery enabled.

### 2 Steps
- **E1** Goal: Extensions block on a clean site. Do: before activating Acme, Settings › Health check › Check again. Pass when: an "Extensions" block says no other plugin adds to YayMatik. Why: core modules aren't listed.
