**Title:** feat: plan 027 — M8 PR A: abandon sweep, cart triggers, stop on order, cart email blocks

## Summary

The backend of M8 (ROADMAP-dev M8.1–M8.5). A cart or checkout left without an order now starts one reminder series for its shopper, and the series stops as soon as they order.

There is no UI yet. The trigger panels, picker sections, "Needs cart tracking" badge and the 5 templates come in PR B. Until then, activate cart workflows by REST.

About 55 files, +2.3k, one commit per checkpoint.

## Checkpoints
- **CP0 Docs: M7 done** (4d1bf9f): ROADMAP-dev marks M7 as merged.
- **CP1 Schema v6, statuses, sweep** (38597ad)
  - `carts` gains `abandoned_at`, `abandon_trigger`, `series_at`, and the status `abandoned`.
  - `CartSweep` runs every 5 minutes (`yaymatik_cart_sweep`; `Cleanup::ensure()` schedules it) and marks at most 200 carts per run. It takes active carts with an email and items, idle past `abandon_minutes`, up to 24 h further back. It does nothing with tracking off.
  - Only a cycle's first abandon fires `yaymatik_cart_abandoned`. That first abandon is the claim, so no `trigger_claims` table: it moves to M6.
  - Activity turns a row active again and keeps `abandoned_at`. A paid order by email now also closes abandoned carts and sets `order_id`.
- **CP2 Triggers, claim, cart data** (de2c76c)
  - `CartAbandoned` and `CheckoutAbandoned`: a cart that reached checkout starts only the second, never both. Subject `cart:<id>`.
  - One series per email in 7 days, read from `series_at`. It is set only when an active workflow takes the cart, so a cart abandoned with no workflow blocks nothing. Unsubscribed shoppers are skipped.
  - `cart` data item (`SavedCart`) and `CartCustomer`: email and first name always come from the row, the rest from the row's own account, never one found by email. `WC_Customer` alone would give an empty email to a shopper who never checked out.
  - `Trigger::category()` joins the catalog; the picker uses it in PR B.
- **CP3 Stop on order** (5e1443b)
  - Paying an order, emptying a cart and cleanup cancel the cart's waiting runs at once (`Cancellation::carts()`).
  - `Trigger::stop_reason()` stops queued and running runs: before the first step, before each step, and after saving a wait. Reasons: "The shopper placed order #N." and "The cart was emptied or deleted."
  - A shopper who returns and leaves again stays in the series.
- **CP4 Blocks, preview, presenter, activate issue** (6a6b494)
  - `cart.items` shows the prices the shopper saw, with live name, image and link; a gone product shows its saved name without a link. `cart.restore_button` and `cart.restore_url`.
  - Preview uses the newest real cart with its link going to `#`, or sample data when there are no carts.
  - Runs list a cart run by the shopper's email ("Cart #id" once gone); `GET /runs/{id}` adds `stoppedByOrderUrl`.
  - With tracking off, Activate returns 400 `cart_tracking_off` on the trigger. An active workflow stays active and can still be updated while its trigger is unchanged.
  - `yayMatikMeta.wc` gains `cartTracking` and `abandonMinutes`, read in PR B.

## Worth a closer look
- `Dispatcher::dispatch` order: the claim writes `series_at` before a run starts. A rate-limited or versionless workflow still blocks that email for 7 days (listed under Cost in decisions M8).
- `Executor::stop_reason()` runs a cart read before every step of a cart run; other triggers return null without a query.
- `RunStore::waiting_ids_for_subjects()` has no `subject` index and uses `KEY status`.

### Browser steps
Q = `SELECT id,email,status,checkout_at,abandoned_at,abandon_trigger,order_id,last_activity_at FROM wp_yaymatik_carts ORDER BY id DESC;` · R = `SELECT id,subject,status,error FROM wp_yaymatik_runs ORDER BY id DESC LIMIT 10;` · Abandon now = `UPDATE wp_yaymatik_carts SET last_activity_at = UTC_TIMESTAMP() - INTERVAL 2 HOUR WHERE id = N;`, then Tools → Scheduled Actions → `yaymatik_cart_sweep` → Run.

1. Load a page: `yaymatik_db_version` 6. Delete `yaymatik_cleanup_checked_at`, reload: Scheduled Actions shows `yaymatik_cart_sweep` every 5 min.
2. Guest cart, no email; Abandon now: Q stays active.
3. Logged-in customer who never checked out: cart; Abandon now: `abandoned`, `cart_abandoned`; R a queued run `cart:N`; it sends with the account email.
4. Guest at classic checkout with an email; Abandon now: `checkout_abandoned`. Same on block checkout.
5. Shopper returns (cart change): Q active, `abandoned_at` kept; run still waiting. Abandon now: abandoned; R no new run.
6. Place the order from that cart: Q ordered; R Cancelled "The shopper placed order #N." at once.
7. Cart abandoned with a waiting run, then empty it: R Cancelled "The cart was emptied or deleted."
8. Second cart with the same email within 7 days; Abandon now: no second run. Unsubscribed email: no run.
9. Preview email on a cart workflow: real cart, Restore button goes to `#`. No carts: "Sample data".
10. Real email in the mail catcher: items table, prices, total, Restore link refills the cart. Open it in Gmail or Outlook web if you can.
