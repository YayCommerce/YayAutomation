## WordPress.org review notes
Short answers for the review thread (U3):
- **Guest email capture without a nonce** (`includes/Workflow/Core/Cart/EmailCapture.php`, `wc_ajax_yaymatik_capture_email`)
  - Checkout pages are often cached, so a nonce in the page would be stale for most guests.
  - The handler checks the request's origin instead (`Sec-Fetch-Site`, `Origin`, `Referer` against the store's own URL; `RequestOrigin`), sanitizes its two fields and rate-limits by session, IP and site.
  - The reply is always the same `{"success":true}`, so it never says whether an address is known.
  - Capture is off unless the store owner turns on cart tracking, and guest capture has its own switch.
- **Hook-name warnings**
  - `yaymatik_modules`, `yaymatik_resendable_emails` and `yaymatik_change_role_allow_all` are prefixed. Plugin Check flags them only because they are passed as class constants (`self::HOOK`, `self::FILTER`, `self::ALLOW_ALL_FILTER`).
  - `woocommerce_add_to_cart_validation` (`includes/Engine/FEPages/RestoreCart.php`) is WooCommerce's own filter. The restore-cart link applies it before it adds each saved line, exactly as WooCommerce's add-to-cart form does, so other plugins can refuse a product.
- **Admin menu package (`vendor-prefixed/`)**
  - YayCommerce's shared admin-menu package, scoped. The free build leaves out its license client and updater (`src/License`).
  - Its other files still name those classes on paths that run only for paid YayCommerce plugins. The build adds a `class_exists` check to each (`dev/scripts/lib/free-admin-shell.php`, in the public repo), so the free plugin never loads license code and never fails when another YayCommerce plugin is installed.
  - The same step adds `defined( 'ABSPATH' ) || exit;` to each of its files.
- **`UnescapedDBParameter` / `InterpolatedNotPrepared` warnings (28)**
  - These are in `RunStore`, `CartStore`, `RunStepStore`, `TriggerClaimStore`, `WorkflowStore` and `CustomerStats`.
  - Each query goes through `$wpdb->prepare()` where it runs. Table and column names are `%i`; values are `%d` / `%s`.
  - What the checker flags is a SQL fragment that holds only placeholders, built from fixed text:
    - `Schema::in()` makes the `%d,%d,…` list for an `IN (…)`, one placeholder per value passed.
    - `$filter` and `$about` are fixed `WHERE` parts with placeholders for the values passed with them.
    - `$busy`, `$columns` and `$set` are lists of placeholders or fixed column names.
  - No value from a request or the database is ever written into the SQL text.
- **Bundled libraries:** listed with versions in `readme.txt`. React, ReactDOM and the JSX runtime are not bundled: the app uses WordPress's own `react`, `react-dom` and `react-jsx-runtime` scripts.
