# Plan: A check product teams run themselves

## Goal
A product team can check its extension without asking YayMatik's team: `wp yaymatik extension check` reports every declaration problem of the extensions on a site, and PHPStan stubs of the public API let their own CI catch wrong calls.

## Approach
Words as in `docs/extensions-roadmap.md` (D13). Builds on `api-names.md` and `extension-scaffolds.md`.

- **`wp yaymatik extension check [<module>]`:** lists each module from an extension with its `requires_api`, then every diagnostic its declarations and templates raise (the same checks registration and `TemplateCheck` already run, read from the diagnostics store), and exits non-zero when one has any. Runs on any site, so a team runs it on its own dev site with its product installed.
- **PHPStan stubs:** `stubs/yaymatik-extension-api.php` holds the public classes and interfaces of `includes/Api` (signatures and docblocks, no bodies), generated by `./run.sh extension-stubs` and checked by a PHPUnit test that fails when `includes/Api` changes without them. Not shipped in the plugin zip; copied with each scaffold.
- `docs/extension-api.md` gains a short "Check your extension" section: the command and the stubs.

## Checkpoints
1. Command, stubs, docs — Risk: 2 — on wp-env with the six scaffolds loaded, `wp yaymatik extension check` reports all six clean; a scaffold given a wrong key reports it and exits 1; PHPStan run over the six scaffolds with the stubs passes; the stubs test fails when a public method changes.

## Out of Scope
- CI in the product repos: each team adds the stubs to its own.
- Cross-repo CI (D21).

## Decisions
Confirmed: D13.
- C1 The command reports what this request recorded (`Diagnostics::recorded()`), and runs the template check itself: the store is throttled to one write per 10 minutes and keeps 24 h, so a fixed declaration would still show there — confirmed (auto)
- C2 On a site without Pro, a template hidden only because of an unknown Pro step (`ProCatalog`) is a note, not a problem: the check exits 0. Any other message on that template stays a problem — confirmed (auto)
- C3 Teams list the stubs under PHPStan `scanFiles`, not `stubFiles` (which PHPStan validates strictly: missing iterable value types, `WC_Order` unknown); the scaffolds pass at level 5 — confirmed (auto)
- C4 Unknown declaration keys stay ignored and out of Health check, but the check reports them as problems (`Diagnostics::note()`, this request only): a typo in an optional key is what a team most needs caught — confirmed (auto)
- C5 Over 50 entries in the request (`Diagnostics::KEEP`): the check warns that the list is cut and exits 1 — confirmed (auto)
